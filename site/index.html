Open-source infrastructure for AI agents

Every byte your agent reads — pinned, diffable, replayable.

Ctx is the lockfile + replay primitive for what agents read. Each external document gets a stable identity, a freshness policy, and a content-addressed snapshot; every run becomes a manifest you can diff against another, replay byte-for-byte without touching the live source, and hand over as evidence.

SHA256(original) == SHA256(replay)

That's the whole contract. Ctx records the hash of every document it delivers into a run, keeps the bytes in a content-addressed store, and can rebuild the run's exact input later — after the source changed, after the API key expired, after the repo was archived. The same digest shows up in your traces and in the evidence bundle you hand to an auditor.

Why

Models are probabilistic. Most context failures aren't.

The retrieval worked, the prompt was fine, the model was fine — the document had changed underneath, and nobody could prove what the agent actually saw. Agent reliability is bounded by context reliability.

stale · unpinned

"It worked on Tuesday."

A policy, price table, or runbook changed and an agent silently started answering from the new version — or the old one. With Ctx every run records which revision it read, and ctx diff tells you what changed and when.

non-reproducible

"Can you rerun exactly that?"

Tracing tools log strings; they can't hand you the bytes again once the source moved. ctx replay reconstructs a run's inputs from the store and re-verifies every hash — no network, no source.

audit · evidence

"What data did the agent consider?"

EU AI Act Art. 12 logging for Annex III systems (from 2 Aug 2026) and SOC 2 reviews ask exactly this. ctx evidence export produces an in-toto Statement with a Merkle root; verify checks it anywhere. Not legal advice — but it is the record.

How it works

Identify. Resolve under policy. Record the run. Prove it later.

01 · identify

A stable URI per document

ctx://acme/policies/refunds points at a source — a file, a GitHub path, an HTTP URL — and survives the bytes changing.

02 · resolve

Freshness is a policy

require_fresh re-verifies every time; allow_stale --max-age 1h reuses; @prod pins a reviewed snapshot by name. Every observation is a content-addressed snapshot.

03 · record

Runs commit manifests

Mount URIs into a run; commit. The manifest is the ordered list of what was delivered, by hash — the lockfile for that piece of work.

04 · prove

Diff · replay · evidence

Diff two runs with the why (source revision, observed-at, tag). Replay byte-for-byte from the store. Export a Merkle-rooted evidence bundle.

What you get

Small surface, sharp guarantees.

Stable identity: ctx://ns/path

Your code, prompts, and evals reference the identity, not a URL or a file path. Move the source; nothing downstream changes.

Freshness policies + movable tags

require_fresh · allow_stale · @tag. Promote what a reviewer approved with one pointer move; production mounts @prod, staging runs fresh.

Content-addressed snapshots

SHA-256 identity for every observation, with source revision (commit SHA, ETag), observed-at, and provenance. Identical bytes dedupe to one blob.

Per-run manifests with provenance-aware diff

Ordered, immutable, records the @ref used. ctx diff run-a run-b prints what changed, from which revision, observed when — then the unified diff.

Byte-exact replay, strict

Rebuild any run's inputs from storage alone and re-hash them. Any mismatch or missing blob fails loudly. Works in embedded mode and against a server.

Evidence bundles

in-toto Statement v1, subject digest = Merkle root over the manifest, redacted resource definitions, replay check. Go and TypeScript produce identical roots; verify runs offline.

Who it's for

Teams who have to answer for what their agents read.

Agent platform teams

One store of truth for the documents every agent consumes; policies instead of ad-hoc caching; diffs when behavior changes between runs.

Regulated products

Finance, insurance, health, public sector: the "what did it see" record as a verifiable file, not a screenshot of a dashboard.

Eval & incident workflows

Pin an incident's inputs as a fixture with one tag; rerun evals against @prod so only the prompt or model varies.

Ctx also isn't a competitor to install-time lockfiles. Microsoft's APM, skills-lock.json, and the "agent.lock" idea pin an agent's static configuration at install; Ctx pins the runtime documents, per run. Different lifetimes, different locks — you want both.

Start

Sixty seconds, no services.

git clone <this repo> ctx && cd ctx && go build -o ctx ./cmd/ctx
./ctx resource add ctx://demo/policies/refunds --source-type filesystem \
    --path examples/refund-agent/policies/refunds.md --policy require_fresh
./ctx run --id run-a ctx://demo/policies/refunds
./ctx replay run-a        # Replay verified: SHA256 match for 1/1 entries.
